# 上线方案 SOP（Phase 7.5 标准步骤）

> 代码推送完成后、[H4] 确认前，必须输出完整上线方案。不是 deploy-checklist 的 8 大类——而是让前端、后端、测试能各自审查的全维度方案。

## 触发时机

Phase 7 代码推送完成 + MR 已创建后。

## 上线方案结构（18 章）

### 必须包含的维度

| 章 | 内容 | 谁审查 |
|----|------|--------|
| 变更总览 | Feature 数 / 仓库 / 文件 / 页面 / API / Dubbo / Service / 定时任务 / DB / 配置 / 外部集成 各维度量级 | 全员 |
| MR 清单 | 按部署顺序列出，含链接+文件数+行数 | 后端 |
| 页面变更 | 改了哪些页面、改了什么、影响哪些用户 + 前端审查要点 | **前端** |
| API 接口变更 | 改了哪些接口、请求方、确认无副作用的接口 + 后端审查要点 | **后端** |
| Dubbo 接口变更 | 新增/修改的 RPC 接口 + 版本依赖 | **后端** |
| 编码改动明细 | 每个仓库逐文件：文件名+类型(新建/修改)+说明 | **后端** |
| 定时任务 | 类名 / Cron / 查询条件 / 通知对象 / 手动触发方式 + 测试审查要点 | **测试** |
| 数据库 | DDL 变更（无则标明）/ 回滚 SQL / 数据审查要点 | **后端+DBA** |
| 配置依赖 | Nacos / 全局变量 / 消息模板 / 权限 / BPM——逐项列状态 | **运维** |
| 外部集成 | 外部系统 / 调用方式 / 超时 / 失败策略 + 集成审查要点 | **后端** |
| **场景级调用链路** | 每个用户操作场景从前端→API→Service→DB/外部的完整链路，标注【新增】改动点 | **全员** |
| **关键技术设计** | 核心设计决策 + 为什么这样做 + 降级方案 | **后端** |
| 风险评估 | 逐项列出风险+等级+影响范围+缓解措施 | **全员** |
| 回滚方案 | 逆序步骤 + 数据回滚 SQL | **运维** |
| 上线验证清单 | 逐项验证内容+方法+预期+负责人（含回归项） | **测试** |
| 监控与报警 | 指标/看板/阈值/报警方式 | **运维** |
| 上线通告 | 执行前/完成后模板 | **PM** |
| 关联文档 | PRD / 技术方案 / 评审 / 测试 全部链接 | **全员** |

### 场景级调用链路格式

```
用户操作 → HTTP 入口
  → Controller/Provider 方法
    → Ability/Service 方法     // 标注【新增】或【修改】
      → DB 操作 / 外部调用     // 标注超时和失败策略
    → BPM/消息/文件 推送
```

每个场景一条链路。不是代码级追踪，而是**操作级**——让测试能按链路写用例，让后端能按链路评估影响。

### 审查要点格式

每个维度末尾追加 checklist，用 `- [ ]` 格式，让审查人逐项勾选：

```markdown
**前端审查要点**：
- [ ] 具体检查项 1
- [ ] 具体检查项 2
```
