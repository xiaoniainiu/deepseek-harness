# Phase 0.5 — 想法深度探索

> 在 brainstorming（怎么做）之前，先回答"做不做、做什么版本"。
> 来源：YC 六追问模式（YC 六追问 + 反谄媚），适配企业内部产品。

## 触发条件

由路由表决定（`README.md` §需求分级路由）：
- **L1 探索型**：完整 6 追问
- **L2 新建型**：精简 3 追问（Q1/Q2/Q4）
- L3/L4：跳过本 skill

也可由 `brainstorming.md` Step 0 自动路由过来。

## 模式路由（进入探索前先判断）

| 模式 | 适用场景 | 诊断风格 |
|------|---------|---------|
| **Startup 模式** | 解决真实业务问题、要上线给用户用 | 严格追问、逼供式、不留情面 |
| **Builder 模式** | 学习/实验/Hackathon/探索性侧项目 | 协作性、激发创意、帮助发散 |

判断方法：问一句"这是要解决真实用户的问题，还是探索/学习/实验？"→ 路由到对应模式。

## 铁律

1. **探索完成前，禁止写任何代码或 PRD**
2. **一次只问一个问题** — 硬停等回答
3. **每个回答必须给出自己的立场** — 第一个答案是抛光版，**追问第二次**才是真洞察
4. **方案呈现后硬停** — 不自动推进到 Phase 1
5. **二次追问协议** — 用户回答后，先确认理解（calibrated acknowledgment），然后从另一个角度再问一次同一问题的本质

## 6 条不可谈判原则（贯穿所有追问）

1. **具体性是唯一货币** — 抽象描述 = 0 信息量，必须逼到人名/频次/场景
2. **兴趣不等于需求** — "这个功能不错" ≠ "我愿意改变行为来用它"
3. **用户的实际行为 > 创始人的描述** — 观察到的 > 说出来的
4. **现状是真正的竞品** — 不是其他产品，是用户当前的 workaround
5. **窄的 > 宽的** — 做 1 件事做到极致 > 做 10 件事都凑合
6. **状态判断先于方案** — 前产品/有用户/有付费 → 诊断压力不同

## 反谄媚禁用词表（这些话永远不说）

```
禁止: "That's an interesting approach"
禁止: "There are many ways to think about this"
禁止: "You might want to consider"
禁止: "That could work"
禁止: "这是个好问题"
禁止: "有很多种方式可以解决"
替代: 直接说判断 + 理由 + 一个让对方不舒服的追问
```

## 6 个追问

| # | 追问 | 揭示什么 | 企业场景示例 |
|---|------|---------|------------|
| Q1 | **需求真实性**：谁在真实场景下被这个问题困扰？频率多高？ | 需求是"有人想要"还是"有人在痛" | "哪个部门的哪些人，多久遇到一次？" |
| Q2 | **现状替代**：用户现在怎么绕过这个问题的？ | 真正的竞争对手是现有 workaround | "用 Excel / 手动操作 / 其他系统？" |
| Q3 | **最痛用户**：说出一个具体的人，岗位，什么事让他最头疼？ | 阻止品类级思考，锁定第一个用户 | "资产管理员张三，每月盘点手动核对 3 天" |
| Q4 | **最窄楔子**：最小的版本是什么？这周就能让那个人用上？ | 阻止"先搭平台"的冲动 | "只做导出按钮，不做完整报表系统" |
| Q5 | **观察验证**：看过用户实际操作吗？有没有让你意外的发现？ | 阻止基于调查问卷的假验证 | "去现场看过管理员怎么盘点吗？" |
| Q6 | **未来适应**：3 年后公司变了，这个方案更重要还是更不重要？ | 过滤短期需求 vs 长期价值 | "数字化转型深入后，需求会放大还是消失？" |

### 按需求级别路由

| 级别 | 执行哪些追问 | 理由 |
|------|------------|------|
| **L1 探索型** | Q1 → Q2 → Q3 → Q4 → Q5 → Q6（全部） | 纯想法需要全面质疑 |
| **L2 新建型** | Q1 → Q2 → Q4（精简） | 问题明确但需验证真实性和最小版本 |

### 每个追问的执行纪律

```
1. 提出问题
2. 硬停 — 等用户回答
3. 给出自己的判断："基于你的回答，我认为 {X}，因为 {Y}"
4. 追问一次："你确定吗？如果 {反例/替代情况} 呢？"
5. 用户确认后 → 进入下一个追问
```

**禁止**：批量提问、跳过追问、不给判断直接进入下一个。

## 方案生成

所有追问完成后，**必须**输出 2-3 个方案：

```markdown
## 方案对比

### 方案 A：最小版本（MVP）
- **描述**：{一句话}
- **工作量**：{估算}
- **风险**：{主要风险}
- **优势**：{为什么选这个}
- **劣势**：{放弃了什么}

### 方案 B：理想版本
- （同上结构）

### 方案 C：{可选的第三方案}
- （同上结构）

## 推荐
方案 {X}，因为 {具体理由}。
```

**强制规则**：
- 必须包含一个最小版本（MVP）和一个理想版本
- 禁止只给一种方案然后问"行不行"
- 每个方案必须有工作量和风险评估
- AI 必须给出推荐并说明理由

## 硬停门禁

方案呈现后，AI **停止执行**，等待用户：
- 选择一个方案
- 要求调整某个方案
- 提出新方案方向

用户选择后，进入 Phase 1（`brainstorming.md` Step 2 或 Mode A）。
