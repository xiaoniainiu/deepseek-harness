# 代码评审模板

## 审查维度

| 维度 | 检查点 |
|------|--------|
| 正确性 | 逻辑是否正确？边界是否处理？ |
| **调用链完整性** | 修改的方法确实被实际流程调用到了吗？有重载遗漏吗？ |
| 层规范 | 是否违反架构分层规则？ |
| 编码规范 | 是否符合 `rules/coding-standards.md`？ |
| 安全性 | 输入校验？权限检查？注入风险？ |
| 性能 | N+1 查询？大数据量循环？ |
| 范围 | 是否超出需求范围？ |
| **跨模块影响** | 与 Phase 2 影响声明对照？六层追踪验证？降级路径？并行冲突？ |

## 输出格式

```markdown
## 代码评审 v{N}

**审查范围**：git diff（本次变更）
**评审轮次**：{N}/2

### 发现

| 级别 | 文件:行号 | 问题 | 建议 | 优先级 |
|------|-----------|------|------|--------|
| P0 | ... | ... | ... | 必须修 |
| P1 | ... | ... | ... | 应该修 |
| P2 | ... | ... | ... | 可以改 |

### 统计

- P0: {count} | P1: {count} | P2: {count}

### 判定

- [ ] P0 = 0 ?
- [ ] P1 <= 2 且每条有理由 ?
- **结论**：PASS / FAIL（原因：...）
```

## 代码评审 vs 单测评审

| | 代码评审（Phase 4） | 单测评审（Phase 6） |
|---|---|---|
| 审查对象 | 业务代码 diff | 测试代码 diff |
| 关注点 | 正确性 + 规范 + 安全 | 覆盖度 + 真实性 + 边界 |
| 额外检查 | — | mock 是否掩盖真实问题？ |
