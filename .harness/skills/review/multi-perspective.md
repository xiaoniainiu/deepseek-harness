# 多视角评审协议

## 触发条件

- Phase 2 需求评审中（模式 A/B 强制，模式 C 可选）
- 补充 `plan-review-template.md` 的维度清单，不替代

## 三个视角

### 视角 1: 产品视角

**角色**：产品经理
**关注点**：
- 用户价值：这个方案解决了什么用户问题？
- 业务逻辑完整性：正常流程 + 异常流程是否都覆盖？
- 边界场景：极端情况下用户看到什么？
- 验收可测性：每个验收标准是否可以自动化测试或手动复现？

**输出格式**：
```markdown
### 产品视角
**优势**: [1-3 条]
**问题**:
- [P0] 描述...
- [P1] 描述...
**建议**: [具体改进方向]
```

### 视角 2: 技术视角

**角色**：架构师
**关注点**：
- 架构适配：是否符合现有分层？是否引入新的架构约束？
- 性能影响：数据量、并发、响应时间是否有风险？
- 可观测性：监控/告警/日志是否设计到位？
- 向后兼容：API/数据结构变更是否兼容？
- 维护成本：方案复杂度是否与收益匹配？

**输出格式**：（同上结构）

### 视角 3: 风险视角

**角色**：SRE / 安全工程师
**关注点**：
- 失效模式：什么情况下功能会完全不可用？
- 数据安全：是否有敏感数据泄露风险？
- 部署风险：发布过程中可能出什么问题？
- 回滚可行性：如果出问题能否安全回滚？上线有成本吗？
- 最坏场景：最糟糕的情况会造成什么影响？

**输出格式**：（同上结构）

## 综合判定

所有**活跃视角**（由路由表 + 需求级别决定）的问题合并去重后：

```markdown
### 综合判定

**活跃视角**: {列出本次触发了哪些视角}（产品/技术/风险 + 战略?/设计?）
**P0 问题总计**: X 条
**来源**: {各活跃视角} 分别贡献 N 条

**判定**: PASS / FAIL

PASS 条件: 0 P0 + 所有 P1 有缓解方案
FAIL 条件: 1+ P0（需修复后重新评审）
```

### 视角 4: 战略视角（路由表控制触发）

**触发**: 由路由表的"战略评审"行决定（L1/L2 强制，L3 条件触发，L4 跳过）
**详细协议**: 加载 `skills/review/strategy-review.md`
**子模块按路由表独立触发**: 前提质疑 / 梦想态映射 / 范围决策 各有自己的触发条件
**输出**: 追加到 review-v{N}.md 的 `## 战略视角` 区段

### 视角 5: 设计质量视角（路由表控制触发）

**触发**: 由路由表的"设计质量评审"行决定（L1/L2 涉及 UI 时强制，L3 建议，L4 跳过）
**详细协议**: 加载 `skills/review/design-quality-review.md`
**输出**: 追加到 review-v{N}.md 的 `## 设计质量视角` 区段

## 自动评审模式（用户可选）

> 当用户说"自动评审"或不想逐个视角确认时，自动执行所有被路由表触发的视角。
> 改编自 autoplan 模式。

### 决策分类

| 类型 | 定义 | 处理 |
|------|------|------|
| **机械型** | 只有一个明显正确答案 | AI 自动决定，静默记录 |
| **品味型** | 合理的分歧空间 | AI 自动决定，但在最终汇总中**高亮展示** |
| **用户型** | AI 无法代替用户判断（如范围选择、功能取舍） | **硬停等确认** |

### 6 条自动决策原则

1. 选完整性（有覆盖胜过精简）
2. 选更简洁的实现（同等功能下）
3. DRY（拒绝重复）
4. 显式优于隐式
5. 偏向行动（可以做的先做）
6. 最小破坏（向后兼容优先）

### 最终门禁

自动评审完成后，输出一次性汇总：

```markdown
## 自动评审汇总

**活跃视角**: {列出本次触发了哪些视角}

### 机械型决定: {N} 条
<details>
<summary>展开查看</summary>
- {决定 1}: {理由}
- ...
</details>

### 品味型决定: {N} 条（请逐条确认或翻转）
- ⚡ {决定 1}: {理由} — 采用原则 #{N}
- ⚡ {决定 2}: {理由}

### 用户型问题: {N} 条（必须回答）
- ❓ {问题 1}
- ❓ {问题 2}

### P0 问题: {N} 条（必须解决后才能 PASS）
- 🚫 {问题}: {来源视角}
```

## 本体增强

如果 `ontology/` 存在，各视角可引用本体：
- 产品视角：检查状态流转是否在本体中有定义
- 技术视角：检查转换覆盖度
- 风险视角：检查 `deny` 规则是否在方案中有考虑

## 输出位置

评审结果写入 `changes/<req>/review-v{N}.md`，以 `## 多视角评审` 区段追加。
