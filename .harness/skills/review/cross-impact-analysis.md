# 跨模块影响分析 SOP（双阶段门禁）

> WHY: V08 五个功能并行开发，三功能同时修改 `VehicleReserveProviderImpl`，
> 驾照校验硬拦截导致数据工场不可用时预约全阻断。
> 这些问题在 Phase 2 可以预判，在 Phase 4 必须验证。

## 适用场景

**所有需求**。简单需求可简化填写，但不可跳过。

## Phase 2 阶段：预期影响声明

### 触发时机

Phase 2 需求评审中，在 `requirement.md` 评审通过前必须完成。

### 操作步骤

```
1. 列出本需求所有改动文件 + 方法
   → grep/搜索确认改动方法被哪些调用方使用

2. 对每个改动方法，追踪所有调用链路
   → 问："除了本需求的场景，还有谁调用这个方法？"
   → 列出每条链路 + 判断是否受影响

3. 检查并行改动
   → 查 Harness/changes/ 和 git branch，是否有其他需求在改同一文件
   → 有 → 标记冲突风险

4. 评估爆炸半径
   → 如果本次改动引入 bug，最多影响几条链路？几个用户群？
   → HIGH/MEDIUM/LOW

5. 填写「跨模块影响声明」到 requirement.md
```

### 影响等级与后续动作

| 等级 | 条件 | 动作 |
|------|------|------|
| HIGH | 改动主流程入口 / 影响 3+ 链路 / 并行冲突 / 外部依赖硬拦截 | **[H-IMPACT] 人工确认**后才能进 Phase 3 |
| MEDIUM | 影响 2 条链路 / 有降级路径 | 记录，Phase 4 重点审查 |
| LOW | 新增代码 / 仅影响本链路 | 记录即可 |

## Phase 4 阶段：实际影响验证

### 触发时机

Phase 4 编码评审中，作为评审通过的必要条件。

### 操作步骤

```
1. 打开 changes/<req>/requirement.md 的「跨模块影响声明」

2. 对照实际 diff 执行六层追踪：

   层1-服务层：
   → 对 diff 中每个被修改的方法，grep 所有调用方
   → 确认每个调用方的行为是否受影响
   → 对照声明中的"受影响链路"，有遗漏 = P0

   层2-SQL生成层：
   → 新增/修改的查询条件，读框架代码确认 SQL 生成逻辑
   → fieldValues 单值 vs 多值？equalsTo vs IN？
   → customSql 拼接是否有注入风险？

   层3-方法签名层：
   → 改动方法有几个重载？每个重载被谁调用？
   → Lombok getter 名是否与代码一致？
   → 重载遗漏 = P0（VIN 校验的重载踩坑）

   层4-Hook/模板内部行为层：
   → 如果涉及前端 hook：hook 是否注入额外参数？
   → 如果涉及消息模板：变量名是否匹配模板定义？
   → 如果涉及 BPM：表单字段映射是否对齐？

   层5-多流程链路层：
   → 同一入口的不同业务路径（如预约/续借/归还）是否全部覆盖？
   → 只改了一条路径但声明了"全覆盖"= P1

   层6-执行门禁层：
   → 运行时过滤条件（type/status 枚举）是否正确？
   → 配置开关/全局变量 key 是否存在且值正确？
   → 权限校验是否会误拦截合法请求？

3. 跨模块专项检查：

   a) 并行改动冲突：
      → 多个功能同时改同一文件时，行号是否重叠？
      → 逻辑是否互斥或有顺序依赖？

   b) 无关模块污染：
      → diff 中是否有不在声明中的文件？
      → 有 → 要么移除（无关改动），要么更新声明

   c) 爆炸半径验证：
      → 实际代码的爆炸半径 vs Phase 2 声明是否一致？
      → 实际 > 声明 → 更新声明 + 人工确认

   d) 降级路径验证：
      → 新增外部依赖不可用时，主流程是否仍可运行？
      → 硬拦截无降级开关 → 评估是否可接受

   e) 内部数据转换：
      → DTO→Entity→VO 转换链中，新增字段是否全部传递？
      → converter/mapper 是否有遗漏？

4. 输出「跨模块影响验证」到 review-vN.md
```

### 门禁判定

```
Phase 4 通过条件（在原有 P0=0, P1≤2 基础上增加）：
  ✅ 六层追踪无 P0 发现
  ✅ 无关模块污染 = 0
  ✅ 与 Phase 2 声明无重大偏差（偏差已更新声明 + 人工确认）
  ✅ HIGH 影响等级的风险项均有缓解措施或人工确认
```

## 实例：V08 审查发现

| Feature | 层 | 发现 | 级别 |
|---------|---|------|------|
| F-04 驾照校验 | 服务层 | submit() 主路径插入硬拦截，数据工场不可用=预约全阻断 | P1 |
| F-04 驾照校验 | SQL生成层 | 字符串拼接 SQL 有注入风险 | P1 |
| F-04 驾照校验 | 多流程链路层 | 仅预约 submit 加了校验，续借未加（如需校验则遗漏） | P2 |
| F-02 VIN校验 | 执行门禁层 | 第三方同步路径是否需豁免 VIN 校验 | P2 |
| F-03 超期提醒 | Hook/模板层 | UMS 模板变量名是推测值，需对齐模板定义 | P2 |
| F-01+F-03+F-04 | 并行冲突 | 三功能同改 VehicleReserveProviderImpl | P2（行号不重叠） |
